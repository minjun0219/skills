# 커밋·PR·리뷰 답글

짧은 글이라 산문 규칙 중 일부만 해당된다. 형식은 저장소 관례와 사용자가 정한 규칙이 먼저이고,
여기서는 문장만 본다.

## 커밋 메시지

- 제목은 `type(scope): 한국어 요약`, 해라체 현재형(`~한다`)으로 쓴다. 저장소 `git log` 가 다른 관례(`~함`,
  명사형)를 쓰고 있으면 그쪽을 따른다.
- 요약은 한 가지 변경만 담고 50자 안팎으로 쓴다. 나열·괄호 부연은 본문으로 보낸다.
- `type(scope):` 접두사, 이슈 번호, 파일·함수명은 고치지 않는다.

| before | after | 이유 |
|:--|:--|:--|
| fix(auth): 로그인 실패 시 재시도 로직을 수행하도록 수정 | fix(auth): 로그인에 실패하면 다시 시도한다 | 빈 동사 |
| docs: 문서 업데이트 작업을 진행함 | docs: 설치 절을 고친다 | 빈 동사, 무엇을 했는지 없음 |
| refactor: 구조적 개선을 통한 안정성 확보 | refactor: 파서 상태를 한 곳으로 모은다 | 명사화, `~를 통한` |
| feat: 사용자에 의해 설정되어지는 옵션 추가 | feat: 사용자가 정하는 옵션을 추가한다 | `~에 의해`, 이중 피동 |
| fix: 테스트가 실패하게 되는 원인 제거 | fix: 테스트가 실패하던 원인을 없앤다 | 자동화된 피동 |
| chore: 새 캐시 레이어를 가지도록 구조 변경 | chore: 캐시 레이어를 추가한다 | have 직역 |

- 업데이트·리팩터링·머지·롤백 같은 굳은 외래어는 바꾸지 않는다. 문제는 어휘의 출신이 아니라 구문이다. [im-not-ai commit-ko]

## PR 본문

- 구조는 저장소의 PR 템플릿이나 정해 둔 형식을 따른다. 여기서는 문장만 본다.
- "본 PR은 ~를 진행합니다", "~에 대한 수정 사항입니다" 같은 머리말 없이 무엇을 바꿨는지부터 쓴다.

| before | after |
|:--|:--|
| 본 PR에서는 캐시 무효화 로직에 대한 개선 작업을 진행하였습니다. | 캐시를 지우는 시점을 쓰기 직후로 옮긴다. |
| 이를 통해 성능 향상을 기대할 수 있을 것으로 보입니다. | 읽기 지연이 줄어든다(측정은 아래). / 효과는 아직 재지 않았다. |
| 주요 변경 사항은 다음과 같습니다. | (도입구 없이 바로 목록) |

## 리뷰 답글

- 결론부터 한두 줄로 쓴다. "좋은 지적 감사합니다" 같은 인사는 빼도 된다.
- before: "말씀해 주신 부분에 대해 검토해 본 결과, 해당 로직은 의도된 동작인 것으로 판단됩니다."
- after: "의도한 동작이에요. 빈 배열이면 조기 반환해야 해서 그렇게 뒀어요."
