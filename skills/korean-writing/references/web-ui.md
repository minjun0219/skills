# 웹·앱 UI 문구

화면에 보이는 문구다. 버튼·라벨·제목·본문·토스트·다이얼로그·폼 오류·빈 상태·플레이스홀더·푸시 알림이 여기에 든다.
값이 끼워 들어가는 문구는 `message-variables.md`도 읽는다. `기계` 열의 뜻은 그 문서 머리말과 같다.

## 먼저 보이스를 정한다

문체는 **제품 단위로** 정한다. 제품에 이미 문구가 있으면 그 체를 따르고, 없으면 처음 한 번 정해서
저장소의 문서(가이드·`AGENTS.md`)에 적는다. 정한 뒤에는 한 화면 안에서 섞지 않는다.

| 보이스 | 쓰는 곳 | 본문 꼴 | 근거 |
|:--|:--|:--|:--|
| 해요체 | 일반 소비자 앱·서비스 | `저장했어요.` `다시 입력해 주세요.` | 토스는 제품 안 모든 문구를 해요체로 쓴다 [토스 UX] |
| 합쇼체 + `-세요` | 업무용 도구, 개발 도구, 공공 서비스 | `저장했습니다.` `다시 입력하세요.` | MS 한국어 가이드, KRDS 예시 [MS][KRDS] |

- 약관·법률 고지는 보이스와 별개로 합쇼체(`-십시오` 포함)로 쓴다. [MS]
- 해요체를 골랐다면 과한 경어를 뺀다. `~시겠어요?`·`~시나요?`·`~께`를 줄이고, `계시다` → `있다`, `여쭈다` → `확인하다`·`묻다`,
  `께` → `에게`. 빼서 어색하면 알고 싶은 정보를 주어로 삼아 다시 쓴다. [토스 UX]
  - 예외: 사용자만 아는 사실을 묻거나 부탁하는 문장(설문 등)은 `~시나요?`를 남겨도 된다.

## 요소별 꼴

종결어미는 위에서 정한 보이스를 따르고, 아래는 **꼴**만 정한다.

| 요소 | 꼴 | 마침표 | 예 |
|:--|:--|:--|:--|
| 버튼·CTA | 동사 어간 + `기`, 또는 명사(구). 무엇이 실행되는지 드러나게 | 없음 | `송금하기`, `저장`, `신청서 제출` |
| 다이얼로그 버튼 | 질문에 대한 답이 되는 동사 | 없음 | `삭제할까요?` → [`삭제`] [`닫기`] |
| 메뉴·탭·라벨·체크박스 | 명사(구) | 없음 | `알림 설정`, `다시 표시 안 함` |
| 화면·다이얼로그 제목 | 명사구, 또는 한 줄 문장·질문 | 없음 (질문이면 `?`) | `계좌 삭제` / `이 계좌를 삭제할까요?` |
| 본문·토스트·스낵바 | 완결된 문장 | 있음 | `사진 3장을 올렸어요.` |
| 진행 중 표시 | `~하는 중…` | 없음 | `저장하는 중…` |
| 폼 오류 (인라인) | 무엇이 문제인지 + 어떻게 고치는지 | 있음 | `이메일 주소에 @가 빠졌어요.` |
| 플레이스홀더 | 예시값만. 지시·설명은 라벨이나 도움말로 | 없음 | `예: 2026. 10. 16.` |
| 빈 상태 | 무엇이 없는지 + 무엇을 하면 생기는지 + 버튼 | 있음 | `아직 저장한 장소가 없어요. 지도에서 ☆를 누르면 여기에 모여요.` |
| 링크 텍스트 | 목적지가 드러나는 말. 같은 화면에서 겹치지 않게 | 없음 | `여기` → `환불 규정 보기` |
| 푸시 제목 / 본문 | `~하기`나 명사형 / 완결된 문장 | 제목 없음, 본문 있음 | `재입고 알림` / `찜한 상품이 다시 입고됐어요.` |

- 근거: 기능 이름은 `~하기`나 명사형 [토스 UX]. 버튼·라벨·체크박스는 마침표 없음, 문장은 마침표 [MS].
  레이블과 도움말은 플레이스홀더가 아닌 레이블로 제공한다 [KRDS]. 버튼 이름은 실행되는 기능을 설명한다 [KRDS].
  푸시 제목·본문 규칙 [토스 UX].
- 다이얼로그의 닫는 쪽 버튼은 출처가 갈린다. 토스는 `취소`가 진행 중인 작업을 취소한다고 오해될 수 있다며 `닫기`를 쓰고,
  MS·KRDS 예시는 `취소`·`예/아니요`를 쓴다. 제품에서 하나로 정한다. `예/아니요`는 질문을 다시 읽어야 답이 되므로
  동사 버튼(`삭제`/`닫기`)을 먼저 고른다.

## 문장 규칙

1. **능동형으로 쓴다.** `됐어요` → `했어요`. 수동형은 서비스 종료·기간 만료처럼 주어(서비스·기간)를 강조할 때만. [토스 UX]
2. **할 수 있는 것을 먼저 말한다.** `없어요`·`안 돼요` 대신 `~하면 할 수 있어요`. 일부 혜택만 막힌 경우 부정형으로 쓰면
   서비스 전체를 못 쓴다고 읽힌다. 정책상 막힌 기능은 부정형을 쓰되 이유를 함께 쓴다. [토스 UX]
3. **명사를 이어 붙이지 않는다.** 한자어 명사는 동사로 푼다. 풀기 어려우면 `{명사}가 {명사}해서`로만 풀어도 된다. [토스 UX]
4. **구체적으로 쓴다.** `보러가기` 단독보다 `예약 내역 보러가기`. [토스 UX]
5. **오류는 탓하지 않고 고칠 방법을 준다.** `잘못된 입력입니다` 대신 무엇이 어떻게 달라야 하는지. 오류가 난 항목 옆에 보이고,
   입력한 값은 지우지 않는다. [KRDS][NN/g][GOV.UK]
6. **경우마다 다른 문구를 둔다.** `필수 항목입니다` 하나로 빈 값·형식 오류·길이 초과를 다 덮지 않는다. [GOV.UK]
7. **사과는 서비스 쪽 잘못에만.** 사용자 입력 오류에 `죄송합니다`를 붙이지 않는다. NN/g는 시스템이 실패했을 때 사과를 권하고,
   GOV.UK는 오류 문구에서 sorry를 뺀다. 둘을 합친 기준이다.
   느낌표로 들뜬 느낌을 내지 않는다(토스는 미니앱 부제에 느낌표를 쓰지 못하게 한다).
8. **글자 수를 맞추려고 띄어쓰기를 빼지 않는다.** 길이 제한이 있으면 말을 줄인다. [토스 UX]
9. **`되어요`는 `돼요`로 쓴다.** [토스 UX]

아래 예문은 해요체 보이스 기준이다. 합쇼체 제품이면 종결어미만 바꾼다(`바꿨어요` → `바꿨습니다`).

| 기계 | before | after |
|:--|:--|:--|
| 검출 | `비밀번호가 변경되었습니다.` | `비밀번호를 바꿨어요.` |
| 검출 | `해당 기능은 사용하실 수 없으십니다.` | `이 기능은 본인 인증을 마치면 쓸 수 있어요.` |
| 검출 | `잘못된 이메일 형식입니다` | `이메일 주소에 @가 빠졌어요.` |
| 판단 | `오류가 발생했습니다.` | `사진이 10MB를 넘어 올리지 못했어요. 10MB 이하로 줄여서 다시 올려 주세요.` |
| 판단 | `삭제 확인` + [`예`] [`아니요`] | `메모를 삭제할까요?` + [`삭제`] [`닫기`] |
| 검출 | `본인 인증 진행 후 서비스 이용 가능` | `본인 인증을 하면 바로 쓸 수 있어요.` |
| 고침 | `저장.` (버튼) | `저장` |
| 고침 | `저장되어요` | `저장돼요` |
| 고침 | `로딩중..` | `로딩 중…` (말을 `불러오는 중…`으로 바꿀지는 판단) |
| 검출 | `성공적으로 저장되었습니다!` | `저장했어요.` |
| 검출 | `[재입고알림] 찜한상품이다시입고됐어요` | `[재입고 알림] 찜한 상품이 다시 입고됐어요.` |

## 화면에 놓을 때

- 한 문구를 여러 컴포넌트에 나눠 담지 않는다. 문장 하나는 키 하나다(`message-variables.md` 1절).
- 줄바꿈 위치를 문자열에 박지 않는다. 한국어는 어절 단위로 줄을 바꾸도록 CSS `word-break: keep-all`을 쓴다.
- 글자 수 제한이 있는 자리(푸시, 탭, 버튼)는 큰 글씨 설정에서 잘리는지 본다. 토스는 푸시 제목 7자, 본문 25자로 둔다. [토스 UX]
- 접근성 이름(`aria-label`, 대체 텍스트)도 사람이 듣는 문구다. 같은 규칙으로 쓰고, 아이콘 버튼은 하는 일을 말한다(`닫기`, `검색`).
