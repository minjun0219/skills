# 번역투·AI 티 패턴 (before → after)

강도: **강** = 한 번만 나와도 고친다 / **약** = 여러 번 겹치거나 다른 신호와 같이 나올 때만 고친다.
출처 표기는 `sources.md`의 약칭이다. 예문은 기술 문서 쪽으로 골랐다.

---

## 1. 피동·무생물 주어

원칙: 행동하는 쪽을 주어로 세운다. 사람이 하는 일은 사람이(또는 생략된 독자가), 코드가 하는 일은 코드가 한다.

| 강도 | before | after |
|:--|:--|:--|
| 강 | 값이 검증되어집니다 | 값을 검증합니다 |
| 강 | 테스트가 실패하게 되는 원인 | 테스트가 실패하는 원인 |
| 강 | 사용자에 의해 트리거되는 버그 | 사용자가 일으키는 버그 |
| 강 | 설정이 완료되어야 합니다 | 설정을 마치세요 |
| 약 | 이 라이브러리는 데이터베이스 초기화를 수행해요 | 이 명령을 실행하면 데이터베이스를 초기화해요 |
| 약 | 이 API는 사용자에게 토큰 발급을 허용한다 | 이 API로 토큰을 발급받는다 |

- 단서: 도구 자체의 동작을 설명할 때는 도구를 주어로 써도 된다("`render`는 조각 배열을 돌려준다"). [토스]
- 이중 피동 짝: 되어지다→되다, 해지다·시키다→하다, 불리는→부르는, 일컬어지는→일컫는. [MS]

## 2. 명사화·빈 동사

원칙: 동작은 동사로 쓴다. `수행/진행/실시/처리/완료 + 하다`는 거의 항상 빼도 뜻이 같다.

| 강도 | before | after |
|:--|:--|:--|
| 강 | 로그 파일을 삭제하는 작업을 수행합니다 | 로그 파일을 삭제합니다 |
| 강 | 시스템 모니터링 수행을 통해 성능 측정을 실시합니다 | 시스템을 모니터링해서 성능을 잽니다 |
| 강 | 리팩터링을 진행했다 | 리팩터링했다 |
| 약 | 구조적 변화와 효율화를 통한 안정성 확보 | 구조를 바꿔 더 안정적으로 만든다 |

- `-적/-성/-화`가 한 문장에 둘 이상 겹치면 풀어 쓴다. [토스][im-not-ai F-4]

## 3. 직역 조사구

원칙: 관계는 조사 하나로 말한다.

| 강도 | before | after |
|:--|:--|:--|
| 강 | 이 API를 통해 데이터를 가져온다 | 이 API로 데이터를 가져온다 |
| 약 | 캐시에 대해 설명한다 | 캐시를 설명한다 |
| 강 | 성능에 있어서 중요한 점 | 성능에서 중요한 점 |
| 약 | 인증과 관련된 설정 | 인증 설정 |
| 약 | 로그에 기반하여 판단한다 | 로그를 보고 판단한다 |
| 약 | 재시도를 위해 큐에 넣는다 | 다시 시도하려고 큐에 넣는다 |
| 약 | 서버에서의 처리 | 서버가 처리하는 것 / 서버 처리 |
| 약 | 효과적인 읽기의 방법 | 효과적으로 읽는 방법 |

- `~에 대해`는 사람도 많이 쓴다. 한 문단에 셋 이상 몰릴 때만 고친다. [im-not-ai A-1]
- `-의`를 뺄 수 없는 경우도 있다("그의 설계"). 금지가 아니라 선호다. [새국어생활]

## 4. have·provide·support 직역

원칙: 영어 동사를 사전 뜻 하나로 옮기지 않는다. 한국어가 그 상황에 실제로 쓰는 말을 고른다.

| 강도 | before | after |
|:--|:--|:--|
| 강 | 이 함수는 세 개의 인자를 가지고 있다 | 이 함수는 인자가 셋이다 |
| 강 | 배경 지식을 가지고 있어야 한다 | 배경 지식이 있어야 한다 |
| 약 | 회의를 가졌다 | 회의를 열었다 |
| 약 | 이 패키지는 스트리밍 기능을 제공합니다 | 이 패키지로 스트리밍할 수 있습니다 |
| 약 | Go 도 지원합니다 | Go에서도 쓸 수 있습니다 |

- `가지다`를 무조건 `하다`로 바꾸지 않는다. 명사에 맞는 동사가 따로 있다(열다·보내다·치르다). [국립국어원]

## 5. 개발 동사와 용어

원칙: 기술 문서의 동사와 용어는 개발자가 실제로 쓰는 말로 쓴다. 번역투를 피하려다 영어 동사를 일상어 하나로
1:1 옮기면 그것도 직역이다. 문법적으로 맞는 말이어도(`결과를 내다`) 기술 문서에서는 개발자의 말을 고른다.

| before | after | 원어 |
|:--|:--|:--|
| 낸다 / 내보낸다 | 출력합니다 | emit / output |
| 그린다 / 그려진다 | 렌더링합니다 / 렌더링됩니다 (화면 표시면 "표시합니다") | render |
| 붙든다 / 붙든 것 | 보류합니다 / 보류 중인 내용 | hold |
| 벗긴다 / 걷어 낸 HTML | 제거합니다 / 제거한 HTML | strip |
| 돌려준 것 | 반환한 출력 | return value |
| 돈다 | 동작합니다 | runs |
| 놓는다 (메모리) | 해제합니다 | free |
| 잰 것 | 측정한 결과 | measured |
| 들이기 전에 | 도입하기 전에 | adopt |
| 가릴 수 없는 | 판단할 수 없는 | can't tell |
| 한도 | 길이 제한 | limit |
| 발송 | 전송 | send |
| 이식 (다른 언어 버전) | 구현 | port |
| `main` 을 따른다 | `main` 브랜치 기준이다 | tracks main |
| 붙일 꼬리 | 붙이는 뒷부분 | tail |
| 확정분 / 누적본 | 확정된 출력 / 누적된 출력 | settled / accumulated |
| 메시지를 통째로 | 메시지 전체를 | whole |
| 바뀐 자리 | 바뀐 부분 / 바꾼 위치 | spot / position |
| 잣대로 잰다 / 로그로 잰다 | 기준으로 검사한다 / 로그로 기록한다 | measure |
| 제 서식을 깬다 | 자기 서식을 깬다 | its own |

`흘려 보냅니다`(데이터를 스트림으로 넣는다)는 이미 자연스러운 말이라 바꾸지 않는다.

학술어·번역어·음차어보다 개발자에게 익숙한 말을 쓴다. 디렉터리·코드 이름은 그대로 둔다.

| before | after |
|:--|:--|
| 코퍼스 | 테스트 케이스 (디렉터리 `corpus/`는 그대로) |
| 백틱 런, 마커 런 | 연속된 백틱, 연속된 마커 |

## 6. 제목·메뉴·이름

원칙: 이름은 두 갈래로 정한다.

1. **개발자가 영어로 부르는 짧은 이름은 번역하지 않는다.** 데모 이름, 문서 첫 페이지 이름 같은 것이다.
   비교 제목의 `vs.`를 `대`로 옮기지 않는다. 그 안의 이름을 한글로 쓸지 영문으로 쓸지는 문서가 그 서비스를
   어떻게 적어 왔는지 따른다: 본문이 `텔레그램`이면 `텔레그램 vs. 슬랙`, 메뉴·데모 이름처럼 영어로 부르는 자리면 `Telegram vs. Slack`.
   영어 약어는 미국식으로 마침표를 찍는다: `vs.`, `e.g.`, `i.e.`, `etc.`
2. **하는 일을 설명하는 이름은 자연스러운 한국어로 쓴다.** 직역 명사구 대신 동사구나 짧은 명사를 쓴다.

| before | after | 갈래 |
|:--|:--|:--|
| 텔레그램 대 슬랙 | Telegram vs. Slack / 텔레그램 vs. 슬랙 (본문 표기를 따름) | 1 |
| 스트리밍 (데모 이름) | Streaming | 1 |
| 개념 (문서 첫 페이지, Concepts) | Concepts | 1 |
| 정규화 전후 (Before and after repair) | 깨진 마크다운 고치기 | 2 |
| 개요 (Overview) | 소개 | 2 |
| 왜 ○○ (메뉴) | 배경 (다른 메뉴처럼 짧은 명사로) | 2 |
| 써 보기 (Try it) | 데모 | 2 |

- 영어 명령형 제목(Try it, Get started)을 그대로 옮기지 않는다. 옮긴 티가 나고 에이전트가 쓴 글처럼 읽힌다.
- 메뉴는 이웃 메뉴와 꼴을 맞춘다. 다른 메뉴가 짧은 명사면 하나만 문장형으로 두지 않는다.
- 절 제목은 내용이 드러나는 말로 쓴다. 예: "왜 또 만들었나"(이미 있는 도구가 있는데 만든 이유를 다룰 때).
- 제목 안의 조사도 본문처럼 자연스럽게: "기호로 끝나는 굵게 뒤에 조사" → "기호로 끝나는 굵게 뒤의 조사".

## 7. AI 관용구·문장 틀

원칙: 포장 없이 명제를 바로 쓴다. 무엇이 아닌지보다 무엇을 하는지를 먼저 쓴다.

| 강도 | before | after |
|:--|:--|:--|
| 강 | 결론적으로, 이 방식이 더 빠르다 | 이 방식이 더 빠르다 |
| 강 | 이는 시사하는 바가 크다 | (삭제, 또는 무엇을 뜻하는지 구체적으로) |
| 강 | 미리보기가 기본인 이유다 | 그래서 미리보기를 기본으로 켰다 |
| 강 | 크게 세 가지로 나눌 수 있다. 첫째, … | (도입구를 빼고 바로 나열) |
| 강 | 세 가지 빈틈이 있습니다. 짐작이 아니라 측정한 결과입니다. | 실제로 확인한 빈틈은 세 가지입니다. |
| 강 | 이 라이브러리는 렌더러가 아니라 브리지입니다. | 이 라이브러리는 마크다운을 완성된 화면으로 바꾸지 않습니다. 에이전트가 쓴 마크다운을 채널에 맞게 다듬어 넘깁니다. |
| 약 | 눈여겨볼 것은 세 가지다 | 세 가지를 보면 된다 |
| 약 | 핵심은 캐시 무효화다 | 캐시 무효화가 문제다 |
| 약 | 출력도 마크다운입니다. 물론 고친 뒤의 마크다운입니다. | 출력도 고친 뒤의 마크다운입니다. |

- `A가 아니라 B` 대구는 영어 직역이 되기 쉽다. 한 문장으로 합친다.
- 비유어(렌더러, 브리지)로 정체를 설명하지 않는다. 앞에서 지운 비유어를 뒤에서 다시 쓰지도 않는다
  ("이것이 브리지 방식입니다" → "렌더러 앞에 두는 방식입니다").
- `물론`, `사실`, `결국` 같은 말버릇 접속어는 빼도 뜻이 같으면 뺀다.

## 8. 문장부호·서식

원칙: 문장부호는 한국어 문장에 필요한 만큼만 쓴다. **줄표(—)로 문장을 잇지 않는다.**

| 강도 | before | after |
|:--|:--|:--|
| 강 | 같은 답을 낸다 — 같은 테스트를 통과해야 한다. | 같은 결과를 출력합니다. 네 구현 모두 같은 테스트를 통과해야 합니다. |
| 강 | 기본값을 바꾼다 — 더하는 것이 아니다. | 기본값에 더하지 않고 통째로 바꿉니다. |
| 강 | 넘긴다 — 고치고, 이스케이프하고, 나눠서 | 고치고 이스케이프한 뒤 길이 제한에 맞게 나눠서 넘깁니다 |
| 강 | 정규화하고, 렌더링하며, 나눈다 | 정규화하고 렌더링해서 나눕니다 |
| 약 | 문장마다 **볼드** | 문단에서 정말 중요한 한 곳만 |
| 약 | 매번 붙는 괄호 영어 병기 `정규화(normalization)` | 처음 한 번만 |
| 강 | 산문 문서의 이모지 머리표 | 뺀다 |

- 줄표 자리는 마침표로 끊거나 접속어로 잇는다.
- 줄표 뒤에 행위를 나열하는 꼴은 영어 분사구문(`, fixing, escaping, and splitting`) 구조다. 동사 순서대로 한 문장에 넣는다.
- 연결어미(-고/-며/-지만/-면서/-아서/-어서) 바로 뒤 쉼표는 LLM 한국어에서 가장 강하게 갈리는 신호다. [KatFishNet]

## 9. 헤지·형식명사·기타

| 강도 | before | after |
|:--|:--|:--|
| 약 | ~할 수 있을 것으로 보인다 | ~할 수 있다 / ~로 보인다 (완곡은 하나만) |
| 약 | 다음 릴리스에 나가는 것이다 | 다음 릴리스에 나간다 |
| 약 | 출력이 갈 곳. (명사구로 끝난 정의문이 계속됨) | 출력을 보낼 곳이다. (표 칸 안이면 명사구 그대로) |
| 약 | 에이전트들이 쓴 문서들 | 에이전트가 쓴 문서 |
| 약 | 지금 렌더링하고 있다 | 지금 렌더링한다 |
| 약 | 그는 / 그녀는 / 이는 / 이를 반복 | 생략하거나 명사를 다시 쓴다 |

- `~할 수 있다`를 단정으로 바꾸지 않는다. 반복될 때 일부만 다른 꼴로 바꾼다.

## 10. 용어 일관성

원칙: 같은 개념은 문서 전체에서 같은 말로 쓴다. 다른 개념에는 다른 말을 쓴다.

- "답"과 "답변"을 섞지 않는다. 하나로 통일한다.
- "채널 때문에 바꿔 쓴 것" / "채널에 맞춰 바꿔 쓴 것"처럼 같은 말을 두 꼴로 쓰지 않는다.
- 비슷한 두 개념은 말을 나눠 쓴다. 예: 스트리밍 입력 단위는 "청크", 길이 제한으로 나눈 결과는 "조각".
- 용어를 바꿨으면 같은 문서·이웃 페이지의 같은 말과 링크 텍스트도 함께 바꾼다.

## 11. 직역·단정 피하기

원칙: 영어 원문의 꼴이 아니라 실제로 무엇이 문제인지, 무엇이 사실인지를 쓴다.

| 강도 | before | after |
|:--|:--|:--|
| 강 | 에이전트는 마크다운을 반듯하게 쓰지 않습니다 / 출력은 온전하지 않습니다 (well-formed 직역) | 에이전트가 쓴 마크다운은 표준 마크다운 변환으로는 제대로 표현되지 않을 수 있습니다. |
| 강 | 스트리밍을 지원하는 변환기가 없습니다. (반례가 있음) | 채팅 채널용 변환기는 스트리밍을 고려하지 못합니다. 살펴본 텔레그램·슬랙용 변환기는 모두 … |
| 강 | 스트리밍을 고려하지 않습니다 (능력이 없는 것) | 스트리밍을 고려하지 못합니다 |
| 강 | 브라우저에서 동작합니다. 서버는 쓰지 않습니다. (`— no server` 흔적) | 브라우저에서 동작합니다. (둘째 문장을 지운다) |
| 약 | 한글 처리는 짐작에 기대고 있습니다. | (독자가 겪는 대표 사례 둘을 든다) |

- 상태를 과장해 단정하지 않는다. "자주 깨져 있습니다"도 과장이다. 문제를 말한다.
- 확인할 수 없는 전칭 단정(`없습니다`, `모든`)은 확인한 범위로 좁힌다.
- 능력이 없는 것은 `-지 않습니다`보다 `-지 못합니다`가 맞다. 일부러 안 하는 것만 `-지 않습니다`.
- 영어 원문의 짧은 덧붙임(`— no server`)을 한국어에 그대로 옮기지 않는다. 앞에서 이미 드러난 사실이면 뺀다.
- 추상적인 진단 대신 독자가 실제로 겪는 구체적인 예를 든다.

| before | after | 규칙 |
|:--|:--|:--|
| 안 닫힌 강조 / 못 닫는 굵게 | 닫히지 않은 강조 / 닫지 못하는 굵게 | 줄여 쓴 부정은 풀어 쓴다 (문서 문체에서) |
| 그걸 그대로 받지 않는다 | 그 마크다운을 그대로 받지 않습니다 | 지시어는 가리키는 명사로 |
| 그 굵게만 | 그 자리의 굵게만 | 지시어가 무엇을 가리키는지 드러나게 |
| 열 수 없는 자리의 별표 | 강조를 열 수 없는 자리의 별표 | 생략된 말을 채운다 |
| 80열에서 줄을 접어 쓴 글 | 한 줄을 80자로 접어 쓴 글 | 생략된 말을 채운다 |
| `\|` 뒤가 있으면 그것이 텍스트입니다 | `\|` 뒤에 글이 있으면 그것을 링크 텍스트로 씁니다 | 무엇을 하는지 채운다 |
| 노션은 예외인데, 노션에는 … 나가기 때문입니다 | 노션은 예외입니다. 노션으로는 … 나갑니다. | 한 문장에서 같은 주어를 되풀이하지 않는다 |
| 구현은 Rust 코어, …, Go 구현이 있고 | Rust 코어, …, Go 구현이 있고 | 같은 말을 되풀이하지 않는다 |
| 실제로 … 실제로 (이웃한 두 문장) | 실제로 … 직접 | 이웃 문장의 같은 부사는 바꾼다 |
| `parse` 가 에러를 반환한다 / API 를 호출한다 | `parse`가 에러를 반환한다 / API를 호출한다 | 영문·코드 뒤 조사는 붙여 쓴다(한글 맞춤법 제41항) |
| `hook` 는 / `token` 를 | `hook`은 / `token`을 | 조사는 읽는 소리의 받침으로 고른다: 훅은, 토큰을 |
| 입력 표기과 | 입력 표기와 | 일괄 치환 뒤 조사(와/과, 을/를, 이/가)를 다시 본다 |
| 확정된 것만 보여 준다 / 고친 것을 센다 | 확정된 출력만 보여 줍니다 / 고친 횟수를 셉니다 | 형식명사 `것`을 가리키는 명사로 |
| 문서 여럿을 / 빈틈 셋 | 여러 문서를 / 세 가지 빈틈 | 수량을 명사 뒤에 붙이는 꼴을 줄인다 |
| 코멘트·PR 본문 / 정규화·렌더·분할이 | 코멘트와 PR 본문 / 정규화, 렌더링, 분할이 | 산문 속 가운뎃점 나열은 `와/과`나 쉼표로 |
| 이 채널에만 쓰인다 / 이 조건은 | 이 채널에서만 쓰입니다 / 이 조건에서는 | 장소·조건이면 처소 조사로 |
| 조각 크기와 무관하게 | 입력을 어떤 크기로 끊어 넣었든 | 추상 명사구 대신 독자가 하는 일로 |

- 표 칸·API 설명도 사용자 문서라면 명사로 툭 끊지 않고 서술로 끝낸다.
  `너비.` → `너비 함수입니다.`, `finish 뒤에:` → `finish 다음에 호출합니다.`, `다른가.` → `다른지 알려 줍니다.`,
  `… 참고.` → `…를 참고하세요.` 코드 주석은 명사형(`바뀌지 않음`)으로 둬도 된다.

## 13. 영어판이 따로 있는 문서

원칙: 한국어판과 영어판은 뜻만 맞으면 된다. 문장 단위로 맞추지 않는다.

- 영어로 자연스러운 표현(Try it, `— no server`, corpus)은 영어판에 그대로 둔다. 한국어에 맞춰 영어판을 억지로 바꾸지 않는다.
- 반대로 한국어판은 영어 문장을 한 줄씩 옮기지 않는다. 한국어 독자에게 필요한 순서와 말로 쓴다.
