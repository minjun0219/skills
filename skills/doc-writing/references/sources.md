# 출처

규칙이 기대는 자료다. 문장을 옮겨 온 곳은 없고, 예시의 글은 새로 썼다.

| 약칭 | 자료 | 쓴 곳 |
|:--|:--|:--|
| NN/g | Nielsen Norman Group, How Little Do Users Read? — https://www.nngroup.com/articles/how-little-do-users-read/ , Text Scanning Patterns: Eyetracking Evidence — https://www.nngroup.com/articles/text-scanning-patterns-eyetracking/ | 요지를 앞에 두기, 제목과 첫 문장만 이어 읽는 skim test |
| LMSYS | Does Style Matter? Disentangling style and substance in Chatbot Arena (2024-08) — https://lmsys.org/blog/2024-08-28-style-control/ | 길이와 마크다운 서식이 선호 평가를 끌어올린다 |
| Zhang et al. | From Lists to Emojis: How Format Bias Affects Model Alignment (ACL 2025) — https://arxiv.org/abs/2409.11704 | 평가자와 보상 모델이 목록, 굵게, 이모지를 선호한다 |
| Tufte | Edward Tufte, The Cognitive Style of PowerPoint (Graphics Press) | 목록이 인과와 우선순위를 지운다 |
| Bezos | Jeff Bezos, 2004년 6월 S-team 메일 (서술형 메모를 쓰게 한 이유) | 같은 무게로 나열하면 중요도와 연결이 사라진다 |
| Wikipedia | Wikipedia:Signs of AI writing — https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing | 굵게 남용, 굵은 라벨 목록, 이모지. 징후만 지우면 문제는 남는다 |
| Google | Google developer documentation style guide, Lists — https://developers.google.com/style/lists , Tables — https://developers.google.com/style/tables | 목록과 표를 고르는 기준 |
| 토스 | 토스 테크니컬 라이팅 가이드 — https://technical-writing.dev/ | 문서 유형 정하기, 개요를 앞에 두기, 예측 가능한 제목 |
| 토스 테크 블로그 | 「5. Technical Writer, 사라질 결심」 — https://toss.tech/article/technical-writing-5 | 규칙을 체크리스트로 주면 기계적으로 적용한다, 원칙마다 예시를 짝짓기 |
| Diátaxis | https://diataxis.fr/ | 문서 유형마다 목적이 다르다 |
| 행안부 | 행정안전부 'AI 친화적 보고서' 가이드라인 (2026년 8월 발표, 언론 보도) | 판단을 담은 개조식을 주어와 서술어가 있는 문장으로 |
| Anthropic | Claude prompting best practices — https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices , Skill authoring best practices — https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices | 프롬프트의 서식이 출력으로 옮는다, 금지보다 할 일로 쓰기, 본문을 짧게 두고 레퍼런스로 나누기 |
| doc-coauthoring | anthropics/skills의 doc-coauthoring 스킬 — https://github.com/anthropics/skills/blob/main/skills/doc-coauthoring/SKILL.md | 맥락 없는 독자로 다시 읽어 보기 |

- 표 기준은 Google 가이드의 "관련 데이터가 셋 이상"보다 느슨하게 "비교 기준이 둘 이상"으로 잡았다.
- "다시 들여다볼 신호"의 수치(한 문단에 굵게 둘 이상, 세 단계 중첩 등)는 실험으로 정한 값이 아니다. 그래서 다시 볼 신호로만 쓴다.
